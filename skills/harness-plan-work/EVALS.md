# Harness-plan-work evaluations

Evaluate whether a fresh agent can execute the first milestone without reconstructing
chat context.

## Cases

| Case | Required signal | Status |
|---|---|---|
| Scoped behavior change with a manifest | Every criterion maps to commands and runtime proof | Pending repository trial |
| Fuzzy goal with product choices | Judgment is surfaced before implementation detail | Pending repository trial |
| Dirty tree and higher-risk follow-up | Baseline, preserved edits, and human gate are explicit | Pending repository trial |
| Missing runtime capability | Plan names prerequisite harness work instead of inventing evidence | Passed 2026-08-11 on `auto-route` |

## Passing bar

The plan fixes its baseline and sources, states goal/non-goals, starts with a thin tracer
when feasible, gives every milestone a binary completion criterion and rollback, maps
every acceptance criterion to evidence, and places explicit gates before unauthorized
actions.
