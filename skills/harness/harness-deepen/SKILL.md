# Harness Deepen

Read [`../harness/references/contracts.md`](../harness/references/contracts.md). Improve one
plane for one real tracer workflow.

## 1. Select the bottleneck

Confirm the current level, cited evidence, tracer impact, desired next level, and risk
class. Choose the smallest capability that removes the blocker. If evidence is stale or
absent, assess before designing.

Completion criterion: one plane, one capability transition, one tracer, and one success
signal are explicit.

## 2. Design the increment

Choose the correct durable layer. Define files, interfaces, verification, rollback, and
manifest change. Prefer existing repository mechanisms. For planning or domain work,
read [`../harness/references/composition.md`](../harness/references/composition.md) and
wrap the installed Matt Pocock capability where available.

Completion criterion: the design changes no unrelated plane and can be validated without
subjective interpretation.

## 3. Implement and prove

Make the scoped change, add or update the narrow validation, and run it. Exercise the
tracer path when the environment permits. Update the manifest only to the level supported
by evidence.

Completion criterion: before/after evidence demonstrates the capability transition, or
the report states precisely why the transition remains incomplete.

## 4. Hand off

Return the shared evidence bundle, rollback path, next bottleneck, and any human judgment
still required.
